# Patina: research log

Наблюдения про ИИ-агентов, сделанные при создании Patina (clean-room аналог Substance 3D Painter). Картинки лежат в `research/`.

## 2026-10-20 — Реверс без бинарника: recon по публичным докам вместо декомпиляции

1. Задача: «используй скилл реверс инжиниринга и сделай мне substance painter».
2. Инструменты: скилл REA (MCP `rea`, 300+ инструментов для бинарников, APK, Electron, WASM) и формат replica-recon: `recon.md` + `features.csv`. Источники собирались через Bing.
3. Результат проверялся по таблице: 157 фич с приоритетом и ссылкой на источник по каждой строке, 68 источников. Колонка `clone` заполнялась по ходу сборки.
4. Что удивило. Painter на машине не установлен, а бинарные инструменты REA без цели бесполезны. Скачивать и вскрывать закрытый бинарник Adobe запрещает clean-room. Значит, «реверс» здесь означает поведение и документацию, а не код. Самая полезная находка recon: в публичном Python API Painter агент может создать слой, но не может нарисовать штрих, прочитать его или повторить. Это и стало главным отличием Patina.
5. Рецепт: если цель закрыта лицензией или её нет на диске, REA остаётся без работы. Recon по докам с source_url на каждой строке даёт те же требования и при этом юридически чист. Раздел «gaps an agent-first clone can exploit» в recon превращается прямо в roadmap.
6. Цифры: 157 строк (must 66, should 56, could 28, wont 7). После сборки must: 40 сделано, 12 частично, 14 нет.
7. Картинки: нет (текстовый артефакт `replica/recon.md`).

Хук: Меня попросили отреверсить Substance Painter, а у агента не оказалось ни одного байта Adobe. Пришлось реверсить документацию, и в ней нашлась дыра, ради которой стоило писать свой редактор.

## 2026-10-20 — Тексели, которые знают свою 3D-точку: швы исчезают сами

1. Задача: рисование кистью по 3D-модели без видимых UV-швов, причём штрихи должны переигрываться в любом разрешении.
2. Инструменты: TypeScript-ядро `packages/core`, проверка через CPU-рендер (`renderSheet`) и браузер приложения (split-вид: 3D рядом с UV).
3. Видел так: в split-вид один мазок через границу UV-острова виден на двух островах UV-развёртки и ложится непрерывно в 3D.
4. Что сработало неожиданно хорошо. Агент сам выбрал схему: растеризовать UV в тексели, у каждого из которых есть 3D-позиция и нормаль. Тогда мазок кисти означает «все тексели в радиусе r в 3D», шум считается в 3D-точке, а кривизна берётся по соседям в 3D. Швов нет просто по построению, отдельной борьбы с ними не понадобилось. Штрих хранится как 3D-путь, поэтому экспорт в 4096 из сессии на 1024 пересчитывается заново, без апскейла.
5. Рецепт: `TexelGrid` (spatial hash по 3D-позициям текселей) + обводка UV-треугольников на 1 тексель, чтобы на краях островов не было дыр.
6. Цифры: изменение параметра слоя при 1024 даёт полный пересчёт примерно за 180 мс.
7. Картинки: `research/2026-10-20-first-smoke.png`.

## 2026-10-20 — Тесты зелёные, а царапины выглядят как горох: ловит только рендер

1. Задача: процедурные маски для умных материалов (edge wear, dirt, dust, scratches).
2. Инструменты: ядро + `examples/smart-sheet.mts`. Это скрипт: он рендерит все 7 умных материалов на одном листе, и агент смотрит лист как картинку.
3. Видел так: только по PNG-листу. Юнит-тесты на маски проходили на каждой итерации.
4. Что сломалось. Царапины сначала были изолиниями шума и выглядели как топографическая карта. Потом агент сделал их отрезками в 3D. Но отрезок пересекает поверхность в точке, и царапины стали точками. Причину агент понял по рендеру: в 3D царапина должна быть тонкой пластиной (диском), тогда её сечение поверхностью даёт линию. Ещё две ошибки поймал тоже лист. Breakup у edge wear давал пятна на плоских гранях; это лечится весом по кривизне. Пыль «сверху» лезла на вертикальные стенки, потому что база была `d*0.5+0.5`, а нужно `d`.
5. Рецепт: на любую процедурную визуальную фичу нужен скрипт-лист со всеми пресетами, и агент обязан смотреть на него после каждого изменения. Тест проверяет числа, а форму проверяет только картинка.
6. Цифры: 5 визуальных проблем (изолинии, горох, пятна edge wear, пыль на стенках, слишком плотная патина у меди). Все пойманы листом, ни одна тестом.
7. Картинки: `research/2026-10-20-smart-materials.png` (финальный лист).

Хук: Все тесты были зелёными, а царапины на металле получились горохом. Нашёл это не тест, а одна картинка, и геометрия царапин оказалась интереснее, чем кажется.

## 2026-10-20 — Профилировка агентом: 3.2 с → 0.27 с без GPU

1. Задача: маски на 1024 пересчитывались секундами, интерфейс замирал.
2. Инструменты: scratch-скрипт `prof.mts` (tsx), замер `performance.now()` по этапам.
3. Видел так: таблица миллисекунд по этапам после каждой правки.
4. Что удивило. Первая гипотеза агента (таблица перестановок для Perlin) почти ничего не дала. Реальные тормоза были в двух местах. Генераторы с порогом считали шум даже там, где результат заведомо 0 или 1. Царапины считали десятки отрезков на каждый тексель.
5. Рецепт: (а) early-out: если база вне окна порога при любом шуме, шум не считать; (б) ленивый `SourceBuffer`, который считает источник только для нужных текселей; (в) табулировать дорогую функцию (царапины → предвычисленные пластины по ячейкам). Бейк: сетка с ячейкой = радиус кривизны, ограничение соседей на ячейку и AO на половинном разрешении.
6. Цифры: полный пересчёт ~9.8 с → ~4.5 с; маска царапин 3.2 с → 0.27 с; бейк 7.8 с → 1.85 с. Всё на CPU, в одном потоке.
7. Картинки: нет.

## 2026-10-20 — Инварианты вместо примеров: incremental == full, live == command

1. Задача: инкрементальный пересчёт (только тексели под мазком) и живой мазок под курсором не должны расходиться с «честным» полным пересчётом.
2. Инструменты: vitest, 15 тестов ядра.
3. Видел так: тесты сравнивают буферы попиксельно.
4. Что поймали. Тест «живой мазок == тот же мазок командой» упал по двум причинам. Команда округляет точки, поэтому коммит не узнавал свой живой мазок и рисовал его второй раз; помог допуск 1e-4. Живой ластик стирал только включённые каналы, а записанный стирал все; у ластика больше нет материала. Ещё первый мазок на слое не распознавался как дозапись из-за условия `from > 0`.
5. Рецепт: для любого кеша или ускорения пиши тест-инвариант «быстрый путь == медленный путь» на случайных данных, а не тест с ожидаемым числом. Агент сам находит расхождения, которые иначе всплыли бы как «иногда мазок двоится».
6. Цифры: 3 расхождения, все найдены тестами-инвариантами, а не руками в UI.
7. Картинки: нет.

## 2026-10-20 — Агент через MCP: ошибка с опечаткой как часть UX

1. Задача: дать агенту рисовать, а не только создавать слои. В Substance это закрыто: API не видит штрихи.
2. Инструменты: свой MCP (stdio, 12 инструментов), CLI `patina`, мост к живому окну (Tauri, 127.0.0.1:47910, bearer-токен). Проверка: scratch-клиент `mcp-client.mjs` говорит с сервером по stdio.
3. Видел так: `render_preview` возвращает PNG, агент смотрит его как картинку.
4. Что сработало. Все действия UI устроены как zod-команды, и одна и та же команда работает из кнопки, CLI, MCP и моста. Опечатка в параметре (`opacty`) возвращает `params: Unrecognized key: "opacty"`, без молчаливого игнора. CLI запускается каждый раз новым процессом, поэтому `paint.stroke` без выбранного слоя падал. Исправлено так: без выбора мазок идёт в верхний paint-слой.
5. Рецепт: `strictObject` во всех схемах. Мазок задаётся тремя способами: 3D-точки, UV или экранные координаты + вид камеры. Агенту проще всего экранные: «линия от (0.35,0.42) до (0.65,0.42) на виде front».
6. Цифры: CLI от `new` до `.glb` с умным материалом и мазком при 1024 занимает около 14 с.
7. Картинки: `research/2026-10-20-mcp-preview.png`, `research/2026-10-20-cli-crate.png`.

Хук: В Substance Painter агент может создать слой, но не может провести по нему ни одного мазка. Мы сделали редактор, где кисть принимает JSON.
